# TEST_PLAN

Приёмочные тесты сайта «CS 1.6 в браузере». Ручные тесты (раздел 2) требуют настоящих браузеров, своей копии игры из Steam, VPS и двух разных сетей, поэтому в среде разработки они не выполнялись. Автоматические проверки (раздел 3) запускаются в CI.

Обозначения требований (из ТЗ):

| Код | Требование |
|---|---|
| R-BR | QA: Chrome, Firefox, Safari |
| R-OFF | офлайн-игра на de_dust2 |
| R-NET | сетевая игра 2+ игроков из разных сетей; «два игрока видят друг друга, пинг отображается» |
| R-FAIL | сценарии: без файлов, обрыв связи, свёрнутая вкладка |
| R-LOAD | загрузчик: папка (FS Access / webkitdirectory) или .zip, проверка valve/ и cstrike/, прогресс |
| R-LEGAL | нет файлов Valve в репозитории, файлы не покидают браузер, футер на каждой странице |
| R-DEPLOY | `docker compose up` на чистой VPS поднимает сайт и сервер; HTTPS, brotli, MIME, кэш |
| R-TURN | TURN для строгого NAT; без ручного импорта сертификатов |
| R-MOD | сверка со списком неподдерживаемых модов Xash3D FWGS |

## 1. Подготовка

- **Стенд:** VPS с публичным IPv4 на интерфейсе, домен `[ДОМЕН]` с A-записью на `[IP_СЕРВЕРА]`, развёрнутый `scripts/deploy.sh --pin` (тест T-12).
- **Браузеры (последние стабильные, 64-бит, настольные):** Chrome (или Edge), Firefox, Safari 17+ на macOS. Дополнительно — Safari 15/16 для проверки нижней границы, если есть такая машина.
- **Файлы игры:** установленный в Steam Counter-Strike (папка `Half-Life` с `valve/` и `cstrike/`). Из неё сделать:
  - `cs16.zip` — `valve/` и `cstrike/` в корне архива;
  - `cs16-wrapped.zip` — те же папки внутри одной папки `cs16/`;
  - `wrong.zip` — любые файлы без `valve/` и `cstrike/` (например, фотографии);
  - `partial.zip` — только `cstrike/`.
- **Сети для онлайна:** сеть A — домашний или офисный интернет; сеть B — мобильная точка доступа (CGNAT, строгий NAT); при возможности сеть C — где закрыт исходящий UDP, кроме 53/443.
- Во всех тестах держать открытыми DevTools → Console и Network. В Chrome для WebRTC — `chrome://webrtc-internals`.

## 2. Ручные тесты

Для каждого теста: шаги, ожидаемый результат, требования. Результат записывать в таблицу раздела 4.

### T-01. Главная, навигация, юридический футер — R-BR, R-LEGAL

1. В каждом браузере открыть `https://[ДОМЕН]/`.
2. Пройти по «Играть», «Серверы», «Как подготовить файлы игры», «Лицензии», несуществующему `#/xyz`.
3. На каждой странице найти текст подвала.

**Ожидается:** на каждой странице, включая «Нужен компьютер» и экран игры (в правом нижнем углу, пока мышь не захвачена), есть дословно «Не связан с Valve. Counter-Strike — товарный знак Valve Corporation». Сертификат валиден (замок), предупреждений о сертификате нет. «Лицензии» показывает тексты `LICENSE.txt` и `THIRD_PARTY_NOTICES.txt`, а не «не найден в этой сборке». В консоли нет ошибок.

### T-02. Офлайн de_dust2 — папка целиком — R-OFF, R-LOAD, R-BR

1. `#/play` → «Выбрать папку игры» → указать папку `Half-Life`.
   - Chrome/Edge: системный выбор каталога (File System Access API), запрос «разрешить просмотр файлов» → разрешить.
   - Firefox/Safari: обычный выбор папки (`webkitdirectory`), браузер может спросить про «загрузку» файлов → подтвердить.
2. Следить за прогресс-баром: «Ищем файлы…» → «Читаем: N МБ из M МБ».
3. Проверить чек-лист: 4 зелёные галочки, «Всё на месте — можно запускать», строка «Пропущено … программы для Windows/macOS/Linux и карты одиночной кампании».
4. Ник `QA-<браузер>`, разрешение «Авто», режим «Офлайн-карта», карта `de_dust2` (выбрана по умолчанию) → «Запустить».
5. Дождаться этапов «Загрузка движка» → «Монтирование файлов N из M», затем карты.
6. Выбрать команду (M или меню), побегать, пострелять, кинуть гранату, открыть консоль кнопкой «Консоль» и выполнить `cl_showfps 1`.
7. В DevTools → Network убедиться, что после загрузки страницы **нет запросов с телом размером с файлы игры** (только `.wasm`, `.pk3`, `/api/*`).

**Ожидается:** de_dust2 загружается за разумное время (< 60 с на обычном ПК), есть текстуры, звук и модели, FPS ≥ 30. Клик по canvas захватывает мышь (Pointer Lock), «Во весь экран» работает (в Safari 15/16 — тоже). Команда консоли выполняется. Файлы игры по сети не уходят.

### T-03. Загрузчик: .zip, обёртывающая папка, отдельные папки — R-LOAD

1. `#/play` → «Загрузить .zip» → `cs16.zip`. Ожидается: прогресс по числу файлов, 4 галочки.
2. Перезагрузить страницу, загрузить `cs16-wrapped.zip`. Ожидается: то же — одна обёртывающая папка допускается.
3. Перезагрузить, раскрыть «Папки valve и cstrike лежат отдельно», выбрать `valve`, затем `cstrike`. Ожидается: галочки появляются по мере выбора, у `liblist.gam` указан источник «— из «valve»» / «— из «cstrike»».
4. Chrome/Edge: после успешного выбора перезагрузить страницу — появляется «Использовать сохранённую папку». Нажать её → браузер спрашивает разрешение → файлы читаются заново. «Забыть» убирает кнопку.
5. Запустить офлайн из любого варианта — карта грузится.

### T-04. Нет файлов, не та папка, неполная копия, битый архив — R-FAIL (без файлов), R-LOAD

1. `#/play`, ничего не выбирать, нажать «Запустить». Ожидается: игра не стартует, подсказка «Сначала выберите файлы игры.», кнопка мигает.
2. «Загрузить .zip» → `wrong.zip`. Ожидается: красная ошибка «В «wrong.zip» не найдено папок valve и cstrike…».
3. «Выбрать папку игры» → любая папка без игры (например, «Документы»). Ожидается: та же понятная ошибка.
4. `partial.zip`. Ожидается: чек-лист с ✗ «valve/liblist.gam — Не найдена папка valve…» и ✗ «Текстуры (*.wad)», подсказка «Не хватает файлов игры — см. список выше.», запуск заблокирован.
5. Переименовать `.rar` или текстовый файл в `.zip` и выбрать его. Ожидается: «Не удалось открыть архив. Нужен обычный .zip (не .rar и не .7z).»
6. Отменить диалог выбора папки. Ожидается: ничего не происходит, ошибки нет.
7. Открыть `https://[ДОМЕН]/#/game` напрямую. Ожидается: переход на `#/play`.

### T-05. Онлайн: подключение одного игрока — R-NET, R-TURN

1. `#/servers`: сервер «Работает». Записать, что показано в колонках «Карта» и «Игроки» (данные или «нет данных», см. KNOWN_ISSUES п. 3) и «Пинг».
2. «Играть» → `#/play?server=main` → выбрать файлы → режим «Подключиться к серверу» → «Запустить».
3. Этапы: «Подключение к серверу — получаем адреса STUN/TURN» → «сервер «…»» → «вход на сервер».
4. В Chrome открыть `chrome://webrtc-internals` → RTCPeerConnection → проверить: `iceConnectionState: connected`, data channel `open`, в Stats — активная пара `candidate-pair` (state `succeeded`, nominated).

**Ожидается:** вход на карту сервера (`START_MAP`), значок пинга в панели показывает «NN мс» (зелёный/жёлтый/красный). Если подключение висит больше 15 с с «Сервер не ответил» — проверить KNOWN_ISSUES п. 1 (`scripts/verify-upstream.sh`), это блокер запуска.

### T-06. Онлайн: 2+ игрока из разных сетей, один — за строгим NAT через TURN — R-NET, R-TURN, R-BR

1. Игрок 1: Chrome, сеть A. Игрок 2: Firefox (или Safari), сеть B (мобильная точка доступа). По возможности игрок 3: Safari, сеть C.
2. Оба подключаются к серверу (T-05).
3. Игрок 2 открывает `about:webrtc` (Firefox) или игрок 1, переключённый в сеть B, — `chrome://webrtc-internals`: в выбранной паре кандидатов локальный кандидат `relay` (адрес `[IP_СЕРВЕРА]`, порт из 49160–49200).
4. Принудительная проверка TURN, если в сети B подключение прошло напрямую: временно закрыть в файрволе VPS `GAME_PORT/udp` и `GAME_PORT/tcp` для внешнего IP одного игрока (например, `ufw insert 1 deny from <ip игрока> to any port 27018`), переподключиться. Ожидается: подключение работает, выбранная пара — `relay`. Затем правило убрать.
5. Игроки встают в разные команды, находят друг друга на карте, стреляют.
6. Каждый нажимает Tab.

**Ожидается:** игроки видят друг друга и движения друг друга без заметных рывков. В таблице счёта (Tab) — оба ника и колонка Ping/Latency с числами. Значок пинга в панели — число. `#/servers` у третьего наблюдателя показывает «Игроки 2 / 16» (если A2S работает, иначе «нет данных» — записать). Relay-кандидат используется в сети B. Ни у кого не было запроса импортировать сертификат.

### T-07. Обрыв связи — R-FAIL (обрыв связи)

1. Игрок в онлайне (T-05). На VPS: `docker compose stop cs-server`.
2. Ожидается в течение ~10–30 с: оверлей «Соединение потеряно» (канал данных закрыт / ICE failed) **или** сообщение движка о таймауте сервера. Мышь освобождена, кнопки «Переподключиться» и «Выйти».
3. `docker compose start cs-server`, подождать 15 с, нажать «Переподключиться». Ожидается: «Подключение к серверу…» → вход на сервер. Если сервер ещё не поднялся — «Не удалось подключиться» с повторной кнопкой.
4. На клиенте выключить сеть (Wi-Fi off / кабель) на 30 с, затем включить. Ожидается: «Соединение потеряно» (ICE failed/disconnected) → «Переподключиться» восстанавливает игру без повторного выбора файлов.
5. `docker compose restart api` во время игры. Ожидается: игра продолжается (API нужен только при подключении).
6. «Выйти» → подтверждение → страница перезагружается на главную.

### T-08. Свёрнутая вкладка 2+ минуты — R-FAIL (свёрнутая вкладка)

1. Офлайн-игра на de_dust2: свернуть окно браузера (или переключиться на другую вкладку) на 2–3 минуты, вернуться. Ожидается: игра продолжается с места, где остановилась, без ошибок. Звук возобновляется.
2. Онлайн-игра: то же на 30 секунд. Ожидается: игра продолжается (возможен короткий «догон»).
3. Онлайн-игра: свернуть на 2+ минуты. Ожидается одно из двух:
   - сервер отключил игрока по таймауту — движок показывает дисконнект или меню. Консоль `retry` или «Переподключиться» возвращает в игру;
   - WebRTC-канал закрылся — при возврате сразу оверлей «Пока вкладка была скрыта, соединение с сервером прервалось» и «Переподключиться».
   **Недопустимо:** зависание без сообщения, необходимость перезагружать страницу. Записать, какой вариант случился, в каком браузере (KNOWN_ISSUES п. 12).

### T-09. Перезагрузка во время игры — R-FAIL

1. Во время игры нажать F5 / Cmd+R. Ожидается: браузер спрашивает «Покинуть сайт?» (`beforeunload`).
2. Подтвердить. Ожидается: открывается `#/play` (файлов в памяти нет), в Chrome/Edge есть «Использовать сохранённую папку», настройки лаунчера (ник, режим, сервер) сохранены.
3. Во время игры нажать «Назад» в браузере. Ожидается: страница перезагружается (движок нельзя переинициализировать), без зависшего движка в фоне.

### T-10. Esc и Pointer Lock — R-BR

1. В игре нажать Esc. Ожидается: мышь освобождается, появляется верхняя панель и подпись в подвале, игра показывает меню.
2. Закрыть меню игры, кликнуть по canvas. Ожидается: мышь снова захвачена. В Firefox/Safari иногда нужен второй клик — допустимо.
3. Консоль сайта: ввести команду, ↑/↓ — история, Esc в поле — фокус возвращается игре. Клавиши, набранные в поле, не уходят в игру.

### T-11. Мобильные и неподдерживаемые среды — R-BR

1. Открыть сайт на телефоне (iOS Safari, Android Chrome). Ожидается: главная, «Играть» → «Нужен компьютер» с причинами; «Серверы» и «Подготовка файлов» доступны; футер на месте; горизонтальной прокрутки нет.
2. Настольный Chrome с выключенным аппаратным ускорением (`chrome://settings/system`). Ожидается: заглушка «Браузер не дал доступ к WebGL 2…».
3. Firefox с `media.peerconnection.enabled=false`. Ожидается: офлайн доступен, «Подключиться к серверу» неактивен с пояснением «Онлайн недоступен: браузер не поддерживает WebRTC».

### T-12. `docker compose up` на чистой VPS — R-DEPLOY

1. Чистая Ubuntu 24.04 с Docker Engine 24+ и compose v2. Открыть порты по таблице README.
2. `git clone … && cd cs16-web && scripts/deploy.sh`. Ожидается: создан `.env` из примера, скрипт подсказывает, что заполнить, и завершается с кодом 1.
3. Заполнить `.env`, оставив `TURN_SECRET=change-me…`. Ожидается: `ОШИБКА: TURN_SECRET содержит значение-заглушку`.
4. Заполнить корректно, `scripts/deploy.sh --pin`. Ожидается: образы скачаны, в `.env` записаны `…@sha256:…`, сборка `web` и `api`, `docker compose ps` — все 4 сервиса `running`/`healthy`, «сайт отвечает: https://[ДОМЕН]/api/health».
5. Проверить с внешней машины:
   ```bash
   curl -sI https://[ДОМЕН]/ | grep -iE 'cross-origin|cache-control|strict-transport'
   curl -sI -H 'Accept-Encoding: br' https://[ДОМЕН]/assets/<xash>.wasm | grep -iE 'content-type|content-encoding|cache-control'
   curl -s https://[ДОМЕН]/api/servers | jq .
   curl -s https://[ДОМЕН]/api/ice | jq .
   nc -vz [IP_СЕРВЕРА] 27016          # должен быть отказ / таймаут
   curl -s -o /dev/null -w '%{http_code}\n' https://[ДОМЕН]/rtc/main/admin      # 404
   curl -s -o /dev/null -w '%{http_code}\n' https://[ДОМЕН]/valve.zip           # 404 / index.html, не архив
   ```
   **Ожидается:** `index.html` с `Cache-Control: no-cache`, COOP `same-origin`, COEP `require-corp`, HSTS. `.wasm` — `Content-Type: application/wasm`, `Content-Encoding: br`, `Cache-Control: public, max-age=31536000, immutable`. `/api/servers` — JSON с `servers[0].id = "main"`, `signalUrl = "/rtc/main/websocket"`. `/api/ice` — STUN и TURN с `username = "<время>:web"`. 27016 снаружи закрыт; `/rtc/main/admin` — 404; `valve.zip` не отдаётся.
6. `sudo reboot`, после загрузки сайт и сервер поднимаются сами (`restart: unless-stopped`).
7. Повторный деплой `git pull && scripts/deploy.sh` — без простоев дольше ~30 с, digest'ы не меняются.

### T-13. Оверлей steamcmd (EXPERIMENTAL) — R-LEGAL, R-DEPLOY

1. На тестовой VPS: `scripts/install-server-files.sh` → `data/hlds/{valve,cstrike}`.
2. `docker compose -f docker-compose.yml -f docker-compose.steamcmd.yml up -d`.
3. Ожидается: сервер стартует, T-05 проходит. Если нет — зафиксировать логи `docker compose logs cs-server` в KNOWN_ISSUES п. 25 и вернуться к файлам образа.
4. `git status` — `data/` не появился в неотслеживаемых (игнорируется).

### T-14. `scripts/check-no-valve-files.sh` — R-LEGAL

1. `scripts/check-no-valve-files.sh` на чистом клоне. Ожидается: «OK: файлов игр в репозитории нет».
2. Негативная проверка во временной ветке: `mkdir -p x/cstrike && touch x/cstrike/a.txt liblist.gam test.bsp && git add -f . && scripts/check-no-valve-files.sh`. Ожидается: код 1, перечислены все три файла. Затем `git reset --hard && git clean -fdx x liblist.gam test.bsp`.

Ожидается: код 1, перечислены все пять файлов. Затем `git reset --hard && git clean -fdx x War3.mpq dota.w3x unit.mdx`.

### T-15. `scripts/verify-upstream.sh` — сверка протокола — R-NET (блокер)

1. На машине с доступом к github.com: `UPSTREAM_REF=7c58854 KEEP=1 scripts/verify-upstream.sh | tee verify.log`.
2. Сравнить с `web/src/net/protocol.ts` по таблице KNOWN_ISSUES п. 1: путь WebSocket, имена полей JSON, кто создаёт data channel и с какой меткой, `ordered`/`maxRetransmits`, адрес в `connect`, trickle или нет.
3. Ожидается: в конце нет «!!! CS_SIGNAL_PATH=… НЕ НАЙДЕН». Все расхождения исправлены в `protocol.ts` и `.env`, после чего T-05 и T-06 пройдены.
4. Там же: `git ls-tree HEAD packages/xash3d-fwgs/xash3d-fwgs` — записать коммит движка в THIRD_PARTY_NOTICES §4. Найти `LICENSE`/`COPYING` в submodule'ах и сверить пункты «лицензию сверить…».

### T-16. Приватность файлов игры — R-LEGAL

1. Chrome: DevTools → Network → Preserve log. Пройти T-02 до конца игры.
2. Отфильтровать запросы по размеру (> 1 МБ): только `.wasm`/`.pk3` с нашего домена, все — GET.
3. DevTools → Application: IndexedDB `cs16-web` содержит только `handles` (handle папки, а не файлы); Cache Storage пуст; localStorage — только `cs16-web:launcher` с настройками.
4. На сервере `docker compose logs web | grep -c POST` — нет POST-запросов, кроме служебных (их быть не должно вовсе).

### T-17. Сверка со списком неподдерживаемых модов Xash3D FWGS — R-MOD

1. Открыть https://github.com/FWGS/xash3d-fwgs/tree/master/Documentation, найти список неподдерживаемых модов и их статус.
2. Найти в нём Counter-Strike / cstrike, Metamod, AMX Mod X, YaPB, а также всё, что касается Emscripten/WebAssembly.
3. Дополнить KNOWN_ISSUES раздел F: что в списке и как это влияет на сайт.

### T-18. Безопасность ввода — R-LEGAL (общая надёжность)

1. Ник `"; quit; echo "` → на blur ник очищается от `"` и `;`; в игре ник отображается без кавычек, игра не выходит.
2. Ник `<img src=x onerror=alert(1)>` → никаких `alert`, в консоли `name "<img src=x onerror=alert(1)>"` как текст.
3. Положить в `cstrike/maps` файл `bad name;quit.bsp` → в списке карт его нет.

## 5. Warcraft III — чек-лист ручной проверки

Warcraft III на сайте работает на движке Warsmash (KNOWN_ISSUES, раздел G). W-01…W-06 проверяют сам движок и DotA (по исходникам DotA неиграбельна — прогон подтверждает или опровергает выводы), W-07…W-10 — встраивание в сайт. Результат каждого шага записать в таблицу в конце раздела, а расхождения с разделом G — в сам раздел G.

**Нужно:** настольный Chrome или Edge (последний, 64-бит); копия Warcraft III: The Frozen Throne **1.26a** (классическая установка с `War3.mpq`, `War3x.mpq`, `War3xLocal.mpq`, `War3Patch.mpq`, у локализованных версий ещё `War3Local.mpq`); своя копия карты `DotA v6.83d.w3x`; Python 3.

### W-01. Сборка

1. GitHub → Actions → `wc3-engine` → последний запуск зелёный (или Run workflow).
2. Скачать артефакт `wc3-warsmash`, распаковать. В `games/wc3/BUILD-INFO.txt` — коммит `d69e772b…`, патч `0001-flomaster-subpath-art-signaling.patch`, «Удалено из сборки: goblin-tinker.webp bg.png», путь `/games/wc3/`.
3. В корне распакованного каталога: `python3 -m http.server 8000`, открыть `http://127.0.0.1:8000/games/wc3/` (localhost — безопасный контекст, OPFS работает).

**Ожидается:** главная Warsmash с тремя плитками (Play, Multiplayer, Manage assets). В DevTools → Network все файлы движка (`engine-worker-boot.js`, `_astro/…`, `CHANGELOG.md`) грузятся из `/games/wc3/`, нет 404 на `/engine-worker-boot.js` в корне.

### W-02. Файлы игры

1. Manage assets → Select Warcraft III folder → папка Warcraft III (браузер спросит про «загрузку» — файлы никуда не уходят).
2. Записать: время до готовности, сколько файлов и МБ показал staging, объём OPFS (DevTools → Application → Storage).
3. DevTools → Network: нет запросов с телом размером с MPQ.
4. Перезагрузить страницу, снова Play — повторной распаковки быть не должно (маркер `.w3-ready`).

### W-03. Мили 1×1 офлайн

Play → Single Player → Custom Game → двухигровая мили-карта из стандартных (например `(2)EchoIsles`) → Start.

**Записать:** время загрузки, FPS (на глаз или DevTools → Rendering → FPS meter), строительство и найм, бой, звук, правый клик (приказы), есть ли компьютерный противник (ожидание по исходникам — нет).

### W-04. DotA 6.83d: загрузка

1. Manage assets → Maps → добавить `DotA v6.83d.w3x` (попадёт в `/w3/Maps/Upload/`). Или заранее положить карту в `Maps/` своей папки Warcraft III и выбрать папку заново.
2. Custom Game → выбрать DotA → Start. Включить в DevTools → Console «Preserve log».

**Записать:** загрузилась ли, за сколько секунд; первые ошибки и предупреждения (`Save as…` в консоли), особенно про нативки.

### W-05. DotA: выбор героя, крипы, способности, смерть, магазины

Патч `vendor-patches/wc3/0003` добавил механики, без которых DotA не играется (KNOWN_ISSUES п. 43–49). Этот тест показывает, хватает ли их. Чат: на карте нажать Enter, ввести текст, Enter — отправить, Esc — закрыть.

| Шаг | Что сделать | Ожидание после патча 0003 |
|---|---|---|
| a | Хост в первые секунды вводит в чат `-ap` (или `-ar`) | карта пишет режим игры на экране |
| b | Выделить таверну рядом со стартовым юнитом, нажать кнопку героя | золото списывается, герой появляется у таверны, стартовый юнит исчезает (это делает триггер карты по событию продажи) |
| c | Подождать ~1,5 минуты игрового времени | волны крипов выходят и идут по линиям |
| d | Прокачать и применить все способности 2–3 героев (с целью-юнитом, с целью-точкой, без цели) | эффект способности срабатывает; записать, какие не сработали |
| e | Умереть (от крипов или башни), подождать | герой воскресает у фонтана через время, зависящее от уровня (таймера на экране нет — п. 45) |
| f | Купить 2–3 предмета, собрать простой рецепт | предметы покупаются, рецепт собирается |
| g | Табло справа | табло нет (multiboard не реализован, п. 49) |
| h | То же на двоих (W-06) | у обоих одинаковые события, нет окна рассинхронизации |

В консоли (DevTools) искать строки про нереализованные нативки — их список пригодится для следующего патча.
